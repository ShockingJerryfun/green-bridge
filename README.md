# Green Bridge

版本：1.3.0

用一个受限 Git 项目在蓝区与绿区之间传递任务和结果。蓝区可以使用支持 `SKILL.md` 的 AI 工具，也可以直接调用脚本；绿区 Windows 运行常驻接收服务，默认执行直接命令。CodeAgent 会话和人工交接是可选功能。

第一次使用时，先在蓝区克隆源码或解压本目录，再按 [接入、认证与首次测试](references/setup.md) 配置两侧。请另行准备自己的受限 Git 项目克隆链接，例如 `https://github.com/<用户名>/<仓库名>.git`；这个项目用于传输派单和结果，与公开的 skill 源码仓库分开。

如果由 AI 协助搭建，可把 Git 项目链接、蓝区系统和绿区系统告诉它，并让它读取本目录的 `SKILL.md` 与接入指南。令牌、密码和私钥只在相应设备本机输入，不发给 AI 或写入 Git 项目。支持技能安装的工具可按自身方式安装 `green-bridge`；其他工具直接读取文件并执行脚本即可。

**传输项目必须受限且符合跨区规则。**任务分支的写入者可以触发绿区服务账户执行命令；结果分支保存原始输出。首次使用请先完成只读往返，确认认证、服务和结果回传均正常。

使用过程中请遵守公司的信息安全政策，尽量避免在任务、命令和结果中传输敏感信息。

本机配置、凭据、服务器清单、任务记录和服务日志不随压缩包分发。计划任务、网络代理和可选代理适配器应在各自目标环境验证。

如需维护本机的服务器别名和使用规范，可将 [服务器资料模板](assets/servers.example.json)复制为 `local/servers.json` 后填写；它只供本机参考。`local/` 已由 Git 忽略；压缩目录时也要排除该目录，因为 Git 忽略规则不会自动影响压缩包。
